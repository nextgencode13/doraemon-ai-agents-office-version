# Architecture Decision Records (ADRs)

## ADR-001: Provider-Independent AI Architecture
- **Status:** Accepted
- **Context:** JARVIS utilizes Google Gemini API initially (due to the system running on an Intel Core i9-14900K with integrated Intel UHD 770 graphics and no discrete GPU). In the future, the system will support local models (via Ollama or local inference) when a GPU is added.
- **Decision:** Business logic and productivity services must **never** import or interact directly with provider-specific SDKs (e.g. `google-genai`). All interactions go through `AIProvider` abstract protocol and `AIService`.
- **Consequences:** Adding Ollama or switching models requires zero rewrites of task, memory, productivity, or desktop subsystems.

## ADR-002: Safety & Permission-First System Operations
- **Status:** Accepted
- **Context:** JARVIS is an AI layer over Windows 11 with task and system execution capabilities.
- **Decision:** The LLM will never have raw or unrestricted PowerShell access. All tools declare risk levels (`SAFE`, `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`), enforce input validation via JSON schemas, and require user confirmation on destructive actions.

## ADR-003: Event-Driven Background Services
- **Status:** Accepted
- **Context:** JARVIS is designed to run for ~14 hours/day as a background personal AI operating layer.
- **Decision:** Background daemons must remain idle/waiting and trigger deterministically on events (e.g. timers, task deadlines, system events). An LLM is only invoked when high-level reasoning or summarization is required.
